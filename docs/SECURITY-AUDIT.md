# سجل الثغرات — Yetimmm v4.18.0 (تدقيق على مرحلتين، ثم إصلاح)

**المنهج:** قراءة كاملة لمسارات الـ Worker (المصادقة، الجلسات، المزامنة، الأخبار/التنبيهات، الـ webhook)، والواجهة (كل مواضع حقن HTML والروابط والرسائل بين النوافذ)، والـ EA (الشبكة، الملفات، الأوامر)، والسكربتات. كل بند له معرّف وخطورة وحالة ودليل.
**الحدود:** التدقيق يدوي + اختبارات آلية على نموذج Cloudflare؛ لم يُجرَ اختبار اختراق حيّ ولا `npm audit` (لا شبكة هنا) ولا ترجمة EA. القرارات الصريحة للمالك محترمة ومذكورة كـ «مقبول».

## فحص عميق ثالث (fuzzing + ماسح أسرار)
- حمولات عدائية (أنواع خاطئة، `__proto__`/`constructor`، أرقام `1e308`/`NaN`، مصفوفات 500 عنصر، JSON مبتور، 70KB، ترويسات غريبة) على **كل** مسارات الـ Worker وعلى مزامنة EA مصادَقة: وجد بنداً W9 وأُصلح؛ بعده صفر 5xx عبر 7 بذور × 700 طلب، وصفر تلويث لـ `Object.prototype`.
- ماسح أسرار على كل الملفات: لا توكنات ولا مفاتيح؛ المطابقات الوحيدة قيم اختبار وإشارة تاريخية قديمة في CHANGELOG (صُحّحت).
- ReDoS: كل التعابير النمطية على مدخلات خارجية بسيطة ومحدودة الطول.

## مقبول بقرار المالك (لم يُغيَّر)
- كلمة السر المشتركة، ورمز CODE_PAIR (من يملكه يستطيع اقتران EA)، و`tok.cfg` في ردّ المزامنة، وحدود المخاطرة.
- **لا قفل ولا حدّ لمحاولات كلمة السر** ⇒ التخمين الآلي ممكن. نصيحة تشغيلية: كلمة سر طويلة عشوائية (16+ حرفاً)، فهي خط الدفاع الوحيد هنا.
- مُقتَرن بـ CODE_PAIR مُخترَق: يستطيع تلويث تقويم سيرفر وسيط عبر `srv` المُدّعى. مخاطرة مقبولة ما دام الرمز سرّياً (`npm run setup` يولّد رمزاً عشوائياً).

## مخاطر متبقية لا يحلها الكود
- مزامنة/نداءات الدليل كلها تمر على Durable Object واحد (`dir`) في مسار رمز الاقتران الخاطئ: تضخيم محدود للطلبات المزيّفة؛ الحل الحقيقي حدّ معدّل على Cloudflare (WAF) وهو خارج الكود.
- أسرار EA (`pair=`, `brsec`) نص عادي على القرص بحكم قيود MT5.
