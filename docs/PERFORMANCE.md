# الأداء: ماذا يتحسّن فعلاً، وكيف تقيسه، وكم يكلّف على Cloudflare (v4.21 / EA 2.33)

## 1) ما الذي يسرّعه الخط السريع وما الذي لا يسرّعه
الأوامر المعلّقة (Buy Stop / Sell Stop) **ينفّذها سيرفر البروكر نفسه** عند وصول السعر. لا الـ EA ولا الـ Worker ولا Cloudflare داخل هذا المسار، فسرعة التنفيذ عند البروكر لا تتغيّر.
ما يتحسّن:
1. **وصول الأمر من التطبيق إلى الـ EA** (ضغطة «تعديل/حذف/تشغيل» ← MT5): بالمزامنة العادية حتى ~1 ث، وبالخط السريع حتى ~0.3–0.6 ث.
2. **حداثة السعر** في الكرت (تيك البروكر الحي نفسه الذي تقرأه الأوامر).
3. **صحة المواصفات** (digits، tick، filling) التي تُقرأ من البروكر المتصل كل ثانية.

## 2) كيف تقيس (بدل أن تثق بالوصف)
افتح الإعدادات ← «قياس الأداء». القيم من الـ EA نفسه (آخر 64 عيّنة، p50 / p95):

| المقياس | ما يعنيه |
|---|---|
| وصول الأمر · خط سريع / مزامنة عادية | من وصول الأمر إلى الـ Worker حتى استلام الـ EA له (`ams` + نصف RTT). **هذا هو مقياس التحسّن.** |
| من لمس السعر إلى الأمر في السيرفر | `g_trigMs` ← الأمر مسجّل عند البروكر. **هذا هو مقياس أن الخط السريع لا يضرّ التنفيذ.** |
| رحلة الشبكة / حجب | RTT الطلب الخفيف ونسبة الوقت التي حجب فيها الخيط (نافذة 10 ث) |
| رحلة السعر للتطبيق / عمر السعر | قياس التطبيق لطلب `/px` وعمر آخر تيك عند الـ Worker |
| طلبات Cloudflare اليوم | العدّاد مقابل الميزانية + معامل الإبطاء |

مقارنة عادلة (A/B): شغّل ساعة بـ `InpBrFastMs=300` وساعة بـ `0` واقرأ «وصول الأمر» و«من لمس السعر إلى الأمر». إن ساء الثاني مع الخط السريع فخفّف `InpBrMaxDutyPct` أو ضع `InpBrFastMs=0`. عيّنات قليلة (n صغير) لا تصلح للحكم؛ انتظر أوامر حقيقية.

## 3) كيف يحمي الخط السريع خيط التداول
WebRequest متزامن: كل طلب يحجب خيط الـ EA الوحيد طوال رحلته. الضوابط (بالترتيب):
1. **منطقة السوق:** بعيد / قريب / ساخن ← نسبة حجب مسموحة 25 % / 8 % / 3 % (`InpBrMaxDutyPct`).
2. **الفاصل** = `RTT × 100 / النسبة` (RTT = 80 مللي ث وبعيد عن المستوى ⇒ 320 مللي ث؛ وقت السخونة ⇒ ≥ `InpBrHotMs` وحتى 3 ث).
3. **مقياس فعلي** لنسبة الحجب في 10 ث: إن تجاوزت المسموح لا يُرسل شيء.
4. **مهلة تكيفية** ≤ 1 ث (0.6 ث ساخن).
5. **قاطع دائرة:** طلب أبطأ من `InpBrLaneMaxMs` ⇒ الخط موقوف `InpBrLaneSuspendSec`.
6. لا خط أثناء `YS_CREATING` ولا قبل أول مزامنة كاملة ولا أثناء الاقتران أو اشتباه نسخة ثانية.
المزامنة الكاملة كل ثانية لا تتوقف ولا تُبطَّأ بسبب الخط، وتحمل الأوامر دائماً.

## 4) أين تذهب طلبات Cloudflare
| المصدر | قبل (طلب/ساعة) | بعد |
|---|---|---|
| مزامنة EA الكاملة (24/7) | 3,600 | 3,600 مع تطبيق مفتوح · **1,200** بلا تطبيق (`IDLE_SYNC_SEC=3`) |
| خط EA السريع | ~12,000 | A ≈ 9–12 ألف · B ≈ 4.5 ألف · C = 0 |
| التطبيق `/px` | ~10,300 | A 10,300 · B 4,500 · C ≤ 1,800 |
| التطبيق `/state` | 3,600 | A 3,600 · B 1,800 · C 720 |
| **المجموع مع تطبيق مفتوح** | **~29,500** | A ≈ 27 ألف (45 ث فقط بعد كل لمسة) · **B ≈ 14 ألف** · **C ≈ 5–6 آلاف** |

وبلا تطبيق مفتوح: ~86,400/يوم ⇒ ~28,800/يوم. الأرقام تقديرية (تعتمد RTT ونشاط السوق)؛ العدّاد الحقيقي في الإعدادات.
حاكم الميزانية (`DAILY_REQ_BUDGET=80000`) يضمن بقاء اليوم تحت الحد بإبطاء تدريجي؛ على الخطة المدفوعة ضع `0`.
