## حالات السيتاب (التقرير §6) مقابل ما هو موجود
لم أُدخل تعداداً جديداً دائماً (READY/SUBMITTING/…): الـ EA يملك أصلاً حالة لكل جانب (`YS_*`: WAITING / CREATING / PLACED / FAILED) وحالة النظام، وتتبّع تذاكر الأوامر عبر GlobalVariables، واستعادة من سجل الوسيط عند التشغيل (`RecoverHistory`, `TrkLoad`). أُضيف فوقها: معرّف سيتاب ثابت، عدّاد محاولات، حجز «غير مؤكد». التقابل:

| تقرير | في الـ EA |
|---|---|
| READY | `YS_WAITING` بلا سبب انتظار |
| SUBMITTING | `YS_CREATING` (+ `g_attempt[s]++`) |
| RETRY_PENDING / FAILED_RETRYABLE | `YS_WAITING` «Retrying (CLASS, attempt N)» + `g_sideNextMs` / `g_nextPlaceMs` |
| ORDER_ACCEPTED | `YS_PLACED` بعد `VerifyPlaced` |
| PARTIALLY_FILLED / FILLED | مركز مفتوح (`OwnPositions>0`) ← لا إرسال ثانٍ إطلاقاً؛ `DONE_PARTIAL` يُعدّ تعبئة |
| FAILED_FINAL | صنف `RCC_FINAL`/`RCC_UNKNOWN` ← محدود ثم `YT_ERROR` |

**فرق صريح:** عدّاد المحاولات وحجز «غير مؤكد» في الذاكرة فقط (لا يُحفظ عبر إعادة تشغيل الـ EA)؛ بعد إعادة التشغيل يُعاد بناء الحالة من أوامر ومراكز الوسيط الفعلية، وهذا ما يمنع التكرار.

## ما لا تستطيع المنظومة فعله (توثيق حالات الرفض النهائي، §11)
- أصناف `FINAL`: `LONG_ONLY` `SHORT_ONLY` `CLOSE_ONLY` `ONLY_REAL` `LIMIT_ORDERS` `LIMIT_POSITIONS` `LIMIT_VOLUME` `HEDGE_PROHIBITED` `FIFO_CLOSE` — تُسجَّل في `Orders.csv` و`Exec.csv` وسجل الخبراء، وتنتهي بـ ERROR بعد 8 محاولات غير مؤقتة.
- حدود الحساب: لا تُتجاوز المخاطرة الصريحة ولا الهامش ولا قواعد الوسيط؛ لا مضاعفة حجم للتعويض.
- أوامر Stop المعلّقة ينفّذها سيرفر الوسيط: لا يمكن للـ EA وضع سقف للانزلاق عليها، لذلك يُقاس ويُعاد حساب المخاطرة بعد التعبئة.
