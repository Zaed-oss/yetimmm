# تقرير إصلاحات الحكم النهائي — Yetimmm v4.29.0 (EA 2.43)
المرجع: «الحكم النهائي لمشروع Yetimmm EA 2.42 — 4.28.0». هذا التقرير يصف ما نُفِّذ وما اختُبر وما **لم** يُختبر.

## ما نُفِّذ (حسب بنود الحكم)
| البند | التغيير | أين |
|---|---|---|
| 1. حد التسلسل | `InpMaxSeqLosses` الافتراضي 20 → **0 (معطّل)**. السقف اختياري، وإن فعّله المستخدم يوقف الأوامر **الجديدة** فقط ويُبقي الدين؛ نص التنبيه يقول «الدين محفوظ». بقية السقوف الافتراضية كانت معطّلة أصلاً (راجعتها واحداً واحداً في الاختبار) | `ea/Yetimmm.mq5` |
| 2. التصفير | `InpResetRiskOnStart` الافتراضي true → **false**. START وتطبيق المستويات بعد STOP يمرّان عبر `ImplicitResetGuarded`: لا يمسّ دَيناً ولا صافياً ولا تسلسلاً ولو فُعّل الإدخال (يسجّل `DEBT_KEPT`). أمر `reset` على دين يحتاج `confirm=1` وإلا `RESET_REFUSED` | EA + `worker.js` + `index.html` |
| 3. دفتر الدورة | مراجعة: الصافي = ربح + عمولة + رسوم + سواب في كل مسار إغلاق؛ الإتمام فقط عند `CycleNet >= الهدف`؛ لا تغيير في المعادلات | مراجعة + اختبارات قائمة |
| 4. الاستعادة | دورة بدين ومستويات صالحة ← تستمر (`RCV_CONTINUE_CYCLE`) بدل IDLE؛ دين بلا مستويات ← `RCV_DEBT_NO_LEVELS` (الدين محفوظ، انتظار `/set` + START لنفس الدورة)؛ `RCV_WAIT_USER` لحالة بلا دين فقط | EA |
| 5. الأوامر | قائمة ممتلئة ← `429 queue_full` (لا قصّ صامت)؛ أمر لم يُؤخذ خلال 120 ث ← `expired` (لم يُنفَّذ)؛ سجل `queued/delivered/expired/rejected` في `/state.cmdStatus`؛ التطبيق يعرض رفض الامتلاء | `worker.js` + `index.html` |

## فلسفة العمل — لم تتغيّر
Stop Buy/Stop Sell وحذف المقابل، التراكم والتسلسل، شروط الدخول، المعادلات، إتمام الدورة بالصافي فقط، لا أمر سوق من البوت. مدخلات الاستراتيجية كما هي عدا الإعدادين الافتراضيين أعلاه (حُدِّث `tests/fixtures/ea-2.39-inputs.txt` لهما فقط).

## الحقيقة بشأن 1000 خسارة متتالية
المنطق لا يضع حدّاً اعتباطياً لعدد الخسائر، لكن لا يمكن ضمان تنفيذ 1000 صفقة: اللوت ينمو أسّياً فيتجاوز حدّ الوسيط أو الهامش قبل ذلك بكثير. عندها تتوقف الأوامر الجديدة بحالة واضحة (`WAITING_VOLUME` / `WAITING_MARGIN`) ويبقى الدين محفوظاً ولا يُدّعى اكتمال التعويض. **لا ضمان لاسترداد الخسائر ولا لمنع خسارة رأس المال.**

## الاختبارات
`npm test`: **288 ناجح / 0 فاشل** (49 Worker + 239 محرك). `npm run check`: كل الفحوص سليمة. الجديد: `tests/continuity-v243.test.mjs` (14: مصدرية + نماذج + Worker حقيقي بنسخة Mock). عُدِّلت اختبارات: `recovery-state-safe` (فرع الدين) وأربعة اختبارات رقم الإصدار والمدخلات.

## ما لم يثبت (صراحةً)
1. **لم يُترجم الـ EA ولم يُشغَّل**: لا MetaEditor هنا. الاختبارات بنيوية ونماذج JavaScript. التعديلات على MQL5 صغيرة لكنها **غير مترجمة**: F7 أولاً.
2. لم تُجرَّب Strategy Tester ولا حساب تجريبي؛ سلامة Netting والهامش ورفض الأوامر غير مثبتة بالكامل.
3. صفقة Netting اختلط بها حجم خارجي لا تدخل الدفتر (لا يمكن نسب نتيجتها للبوت) — قد يُسقط ذلك جزءاً من دين في هذه الحالة الخاصة؛ يُنصح بحساب Hedging.
4. حالة الأمر «نُفِّذ/فشل» الفعلية تأتي من سجل أوامر الـ EA؛ أمر سُلِّم للـ EA ثم أُعيد تشغيله قبل معالجته يظهر `delivered` لا `executed` (يُحسم برؤية الحالة بعد الإقلاع). لم أضف تأكيد تنفيذ مستقلاً في الـ EA.
5. `REQUIRED_RECOVERY` و`cmdStatus` لم يُعرضا بعد كحالة مستقلة في واجهة الـ Mini App (يظهران في `/state`، التنبيهات، `Orders.csv`).
